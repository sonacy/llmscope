# Implementation Plan: llmscope

> Generated by `/plan` on 2026-04-24
> Targets PRD at `./prd.md` and architecture at `./architecture.md`. Six-package Bun monorepo, locked design.

## Overview

Build llmscope as a six-package Bun workspace: a Hono daemon backed by `bun:sqlite` (with FTS5), a React+Vite SPA, a Bun CLI, a shared `core` library defining the addon contract via Zod, plus a TS whistle plugin and a single-file Python mitmproxy addon. Steps proceed bottom-up: contract + storage first, then ingest path end-to-end (so by step 18 a real addon POSTs a real event that renders in a placeholder UI), then UI features, then polish/CI.

## Prerequisites

- [ ] Bun ≥ 1.1 installed locally (FTS5 baked into `bun:sqlite` from 1.1+).
- [ ] Python 3.11+ available for mitmproxy addon dev/test.
- [ ] `whistle` and `mitmproxy` installable for end-to-end smoke (CI uses fixtures, not real proxies).
- [ ] Node 20+ available for tooling that won't run on Bun (rare; Vite preferred via Bun).
- [ ] Empty git repo at `/Users/gulei/code/ai/llmscope/`.

### Step 16: `daemon` — ingest pipeline (without route): derive + persist

- **Description**:
  - `packages/daemon/src/ingest/pipeline.ts`: `processIngest(db, raw): { id }`:
    1. Parse with `IngestEventSchema`.
    2. Compute `host` from URL.
    3. `provider` = `hint.provider ?? detectProvider(url)`.
    4. `model` = `hint.model ?? extracted from request_body JSON`.
    5. Run `attribute()` over UA + host + parsed body using fingerprints loaded fresh from DB on every call (no in-memory cache — additions via `POST /api/sources` must take effect on the very next ingest without daemon restart).
    6. Compute `latency_ms = ts_end - ts_start`.
    7. Extract `prompt_tokens`/`completion_tokens` from `reassembled.usage` or response body.
    8. Insert via repo.
    9. Defense-in-depth: re-run mask on request_headers using `DEFAULT_MASK_HEADERS` (in case addon failed to mask).
  - Tests: feed Sample A (OpenAI SSE) → row inserted with `provider=openai`, `source.kind=codex`, tokens populated; feed unknown UA → `source.kind=unknown` fallback; unmasked Authorization in payload gets re-masked; **insert a new user fingerprint row directly into DB, then ingest a matching event → resulting row carries the user-defined source label (proves no stale cache)**.

## Risks

| # | Risk | Severity | Mitigation |
|---|---|---|---|
| R1 | Whistle plugin API may not expose WS frames bidirectionally → no Realtime capture on whistle path. | High | Step 37 starts with a probe test before implementing. If unsupported: document, ship anyway, advertise mitmproxy as the WS path. Don't block release. |
| R2 | `bun:sqlite` FTS5 not enabled in user's Bun build. | High | Step 14 includes an FTS5 probe at migration time with a clear error pointing at this risk. Fallback path: ship a config flag `search_mode: 'fts5'\|'like'` with `LIKE '%q%'` as the fallback (slower but functional). Document in `docs/known-limitations.md`. |
| R3 | mitmproxy addon can't read `~/.llmscope/token` due to macOS TCC sandboxing. | Medium | Step 38 reads token from `LLMSCOPE_TOKEN` env first; CLI's `install mitmproxy` step (32) prints `LLMSCOPE_TOKEN=$(cat ~/.llmscope/token) mitmdump -s ...` as the canonical invocation. File-read kept as fallback for Linux. |
| R4 | Daemon-down event loss in addon (in-memory ring buffer only). | Medium | v1 acceptance: ring buffer 1000 events + warning logs. Document in `docs/known-limitations.md` (step 47). Persistent ring is a v2 design extension flagged in architecture note 3. |
| R5 | Body cap may leak secrets via truncated request bodies. | Medium | Step 4 + step 16 mask headers; bodies are NOT body-scanned in v1 (PRD scope). Document in `docs/security.md` (step 47). v2: regex sweep for `sk-…`/`AKIA…` patterns inside bodies. |
| R6 | Token file race on first daemon start (multiple `llmscope start` simultaneously). | Medium | Step 13 uses `O_CREAT\|O_EXCL` then read-fallback on EEXIST. PID file write also uses exclusive create; `start` is idempotent (step 29). Cross-platform PID file semantics covered by `process.kill(pid, 0)` liveness probe. |
| R7 | CORS / DNS-rebinding misconfiguration exposes API to malicious pages. | High | Step 25 implements explicit allowlist (`127.0.0.1:<port>` and `localhost:<port>` only); Host-header guard in step 12 already rejects rebinding. CSP on UI's `index.html` set to `default-src 'self'` (step 39). Manual security test in step 47 docs walkthrough. |
| R8 | SQLite write contention at burst load (1000-event spikes from replay tests). | Medium | Step 17 uses single-row inserts initially; if step 49 perf test fails, switch to a 50-row batched ingest queue (architecture risk R4 fallback). WAL+`synchronous=NORMAL` at step 14. |
| R9 | Cross-platform PID file semantics on Windows (process.kill, exclusive open). | Medium | Step 27/29 abstract via `lib/pid.ts` with platform branches. Windows tested manually for v1 (per architecture); CI covers macOS + Linux only (step 48). Document in known-limitations. |
| R10 | Provider streaming format drift (OpenAI/Anthropic change SSE shapes silently). | Medium | Step 8/9 always preserve `raw_sse` and `ws_timeline` so UI can render raw on reassembly empty.
